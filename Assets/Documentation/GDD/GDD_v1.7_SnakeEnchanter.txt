2. High-Level Concept

2.1 Elevator Pitch

In Snake Enchanter, the player is a wounded warrior trapped in a collapsed ancient ruin, racing
against failing health to reach the only escape: a distant window. Unable to fight in their weakened
state, the warrior uses discovered magical melodies to command snakes—moving them aside,
lulling them into a daze, or conjuring a protective shield. Each melody requires precise timing:
hold the tune key to charge a slider, then release when the marker enters the glowing trigger
zone. Release too early and the charm fizzles harmlessly; release too late and the snake strikes
back. Time is the enemy—health depletes continuously as the warrior weakens.

2.2 Core Fantasy

The player is a warrior, but not in fighting condition.
Music becomes the weapon when physical strength fails.
The ruins are unstable; snakes are both danger and obstacle.
Every second counts—the warrior is injured and weakening.
Skillful command—precise slider timing—extends survival; mistakes are costly.

2.3 Target Audience

Age 16+, casual-to-mid-core players, no specific genre experience required.
Should understand goal and controls within 30–60 seconds.

2.4 Project Goals (Theme B Alignment)

• Deliver a clear, understandable core mechanic (slider-based snake command with timing skill).
• Provide a short, replayable experience (5–8 minutes per run).
• Implement two modes (Simple, Advanced) from same core level and systems.
• Integrate database-backed stats to reflect player performance.
• Support a highly readable, trailer-friendly experience.

3. Game Structure

3.1 Game Loop

1. Main Menu → Mode selection (Simple / Advanced).
2. Story Intro screen (atmospheric text, any key to dismiss with fade-in/out).
3. Core gameplay: move through ruin, charm snakes, manage health depletion.
4. Health management:
   a. Health drains passively over time (wounded warrior).
   b. Successful Move/Daze casts restore HP (motivational boost).
   c. Snake attacks deal HP damage (unless Shield is active).
5. Reach window (win) or health reaches 0 (lose).
6. Win: Ending Story screen (happy ending text, any key to dismiss) → Result Screen.
7. Lose: Immediate Result Screen.
8. Result Screen: shows stats + sends data to backend.
9. Option: Retry (same mode) or return to Main Menu.

3.2 Session Length

Target: 5–8 minutes per run (both modes).
Simple Mode drain: ~0.115 HP/sec → ~4.3 minutes to drain from 30 HP at no HP gain.
Advanced Mode drain: ~0.25 HP/sec → ~2 minutes to drain from 30 HP at no HP gain.
HP restoration from successful tune casts extends survival time significantly.

3.3 Modes (Elective Content – 2 Modes)

Mode 1 – Simple Escape
• All 3 core tunes (Move, Daze, Shield) available from start.
• Passive health drain: ~0.115 HP/sec.
• No additional time pressure.
• Objective: Reach the window with HP > 0.

Mode 2 – Advanced Escape
• All 3 core tunes from start.
• Passive health drain: ~0.25 HP/sec (approx. 117% of Simple drain rate).
• Snake attack damage ×1.15 compared to Simple mode.
• Objective: Reach window with HP > 0.

4. Core Gameplay & Mechanics

4.1 Player Abilities

Movement: Free 3D first-person movement using WASD + Mouse.
Camera: First-person view with Cinemachine v3.x (tracks head bone position).
Crouch: Left Ctrl (crouch walk, 50% speed).
Tune Casting: Hold key 1, 2, or 3 → release within trigger zone.
Full body visible: Player's arms and feet visible in first-person view (Pirate Humanoid model).

4.2 Tune System (Core Mechanic) – Genshin-Style Hold & Release Slider

Core Mechanic:
Each tune is mapped to a single key (1, 2, 3 – not Numpad). Player holds the key to charge a
slider from 0% to 100%. A colored trigger zone marks the success area. Player must release the
key when the slider position is within the trigger zone. Casting requires a snake to be in range.

Slider Behavior:
• HOLD KEY: Slider moves continuously from 0% toward 100%.
• RELEASE KEY: Current slider position is evaluated against trigger zone.
• Slider speed determined by tune duration (shorter duration = faster slider).
• Cooldown applies between casts (same key).

Three Possible Outcomes:

1. TOO EARLY (Release before trigger zone):
   • Charm fizzles – no effect.
   • Snake returns to idle state.
   • No damage to player (safe fail).
   • Player can retry immediately.

2. SUCCESS (Release within trigger zone):
   • Charm succeeds – snake obeys command (or Shield activates).
   • Player health restored for Move/Daze (+X HP). Shield does NOT restore HP.
   • Visual/audio confirmation feedback.
   • Player spell animation plays.

3. TOO LATE (Release after trigger zone OR slider reaches 100%):
   • Charm breaks – loss of control.
   • Snake becomes aggressive and attacks.
   • Player takes HP damage.

Tune Parameters (IMPLEMENTED):

| Tune   | Key | Slider Duration | Trigger Zone | Effect                                      |
|--------|-----|-----------------|--------------|---------------------------------------------|
| Move   | 1   | 3 seconds       | 40-65%       | Snake moves away from player path           |
| Daze   | 2   | 4 seconds       | 35-60%       | Snake enters two-phase enchanted state      |
| Shield | 3   | 5 seconds       | 30-55%       | Player shielded from next snake attack (8s) |

Note: Tune 4 (Freeze) was removed from v1.0 scope. See Section 13.

Visual Slider Cue:
• Location: Center-bottom of screen, visible during tune cast.
• Visual: Horizontal segmented bar with moving marker.
• Zones: Yellow (before), Orange (trigger zone = success), Gray (after).
• Trigger zone highlighted with colored segments.
• Disappears on key release.

Audio Feedback:
• Melody plays on SUCCESS only (not during hold).
• Too Early: No melody, silent.
• Too Late: Snake hiss + attack.

4.3 Tunes (Implementation Detail)

Tune 1 – Move Command
• Key: 1
• Slider Duration: 3 seconds.
• Trigger Zone: 40-65%.
• Effect: Targeted snake moves away to a designated MoveAwayTarget position.
• HP Restoration: +X HP on success.
• Active Effects UI: "MOVE" text displays for 3 seconds in corner.
• Player Animation: Spell Casting (Mixamo).

Tune 2 – Daze Command (formerly "Sleep")
• Key: 2
• Slider Duration: 4 seconds.
• Trigger Zone: 35-60%.
• Effect: Two-phase enchantment:
  Phase 1 – Entranced (3 seconds):
    - Amber/orange glow on snake.
    - Snake collision disabled.
    - Snake stays in place.
  Phase 2 – Dazed (8 seconds):
    - Blue glow on snake.
    - Snake plays Die animation (collapses).
    - Collision remains disabled.
    - IsDazed parameter = true (prevents idle reset).
• HP Restoration: +X HP on success.
• Active Effects UI: "DAZE" text displays for 11 seconds (3s + 8s) in corner.
• Player Animation: Wide Arm Spell Casting (Mixamo).

Tune 3 – Shield Command (formerly "Attack")
• Key: 3
• Slider Duration: 5 seconds.
• Trigger Zone: 30-55%.
• Effect: Activates ShieldComponent on player.
  - Duration: 8 seconds (configured via TuneConfig ScriptableObject).
  - Absorbs: The very next snake attack that hits the player.
  - On absorb: Shield breaks, displays feedback, no HP damage taken.
  - On expire: Shield deactivates silently.
  - "SHIELD" text visible in Active Effects window while active.
• HP Restoration: None (Shield is defensive, does not restore HP).
• Player Animation: Magic Spell Casting (Mixamo).

REMOVED – Tune 4 (Freeze Command):
• Removed from v1.0 scope. Code base is clean (no Freeze dead code).
• Future Feature: could be re-added in a post-submission update.

4.4 Health & Failure

Health System:
• Continuous HP scale: 0–100.
• Starting HP: 30/100 (player begins injured).
• Display: Health bar UI (left side) with gradient fill (Green → Yellow → Red).
• Pulse animation: activates below 30% HP.

Passive Health Drain:
• Simple Mode: ~0.115 HP/sec.
• Advanced Mode: ~0.25 HP/sec.

Health Restoration (on successful tune cast):
• Move success: +HP (Move tune).
• Daze success: +HP (Daze tune).
• Shield success: NO HP restoration (Shield is defensive only).
• Cannot exceed 100 HP cap.

Shield System:
• Activated by Tune 3 (Shield) on success.
• Blocks the very next incoming snake attack.
• All snake damage paths route through HealthSystem.TakeSnakeAttackDamage() which checks shield.
• ShieldText TMP visible in Active Effects window while shield is active.

Snake Attack Damage:
• Triggered by: (1) Slider too late / too far / breath attack. (2) Direct collision with active snake.
• Advanced Mode: Damage ×1.15 compared to Simple.
• All damage routed through TakeSnakeAttackDamage() → Shield intercept check → TakeDamage().
• Visual feedback: Health bar flash.

Death Condition:
• HP ≤ 0 → immediate game over.
• Death animation plays based on cause (Drain vs Snake Attack).
• Result screen shown; session data sent to backend.

UI Health Warnings:
• Below 50% HP: Health bar shifts to yellow.
• Below 30% HP: Health bar turns red, pulse animation activates.

4.5 Win & Lose Conditions

Win (both modes):
• Reach the window exit trigger with HP > 0.
• Ending Story screen plays → Result Screen with stats.

Lose (both modes):
• Health reaches 0.
• Result Screen with stats shown immediately.

7. Technical & Data

7.1 Engine & Performance

Unity 6 (6000.0.62f1) with Universal Render Pipeline (URP).
Target: 60 FPS on school laptops, Windows, 1920×1080 + ultrawide.
Input: Unity New Input System (Package) exclusively. Legacy Input FORBIDDEN.
Camera: Cinemachine v3.x — CinemachineBrain on Main Camera, CM_PlayerCamera tracks
  CameraTarget (empty GameObject under Head Bone in Pirate skeleton).

7.2 Snake AI

NavMesh-based movement via com.unity.ai.navigation v2.0.9.
NavMeshSurface baked on GameLevel scene.
NavMeshAgent on each Snake Prefab.

SnakeAI v2.1 State Machine:
• Patrol: Random NavMesh destinations within patrol radius.
• Follow: NavMesh chase toward player when detected.
• MoveAway: NavMesh path to MoveAwayTarget (dedicated GameObject per snake, not child).
• Entranced: Movement stopped, amber glow, collision disabled. Timer 3s → transitions to Dazed.
• Dazed: Blue glow, Die animation, all movement stopped. IsDazed=true prevents idle reset.
• Dead: Snake collapsed from Daze. Remains in collapsed Die animation.
• Breath Attack: Basic Snakes without breath use FollowPlayer instead in breath range.

Snake Types:
• Basic Snake (Toon Snake): Patrol + Follow + Bite attack.
• Advanced Snake (Toon Cobra): Patrol + Follow + Bite + Breath Attack.

9. Risks & Open Questions

9.1 Design Risks (CURRENT STATUS)

Teaching cost: Slider mechanic + 3 tunes could overwhelm players.
Status: Mitigated by Story Intro text and Controls Overlay in-game.

Trigger zone balance: Too narrow = frustrating; too wide = trivial.
Status: Values calibrated during playtesting. Final values locked.

"Too Early" being too safe: Players might always release early.
Status: No HP on too-early; must succeed to heal. Mitigation holds.

9.2 Technical Risks (RESOLVED / DEFERRED)

Slider precision: RESOLVED — Time.deltaTime based slider, tested.
NavMesh Patrol animation jump: RESOLVED — In Place clips, applyRootMotion=false, LateUpdate sync.
Unity Recorder audio: RESOLVED — Debounce flag in MusicManager v1.1.
HTTP DELETE/UPDATE: DEFERRED — Not in v1.0 scope.
Spell Scroll in Scene: DEFERRED — _unlockAllOnStart=true bridges this.

13. Scope Changes (Deviations from Original GDD)

This section documents intentional deviations from the original design.

| Original Design | Actual Implementation | Reason |
|-----------------|----------------------|--------|
| Tune 3: Attack (snake attacks enemy) | Tune 3: Shield (player protection) | Enemy/creature system too complex for solo MVP |
| Tune 4: Freeze (all creatures freeze) | Removed from v1.0 | Overlapped with Daze; out of scope |
| Tune 2: Sleep (snake sleeps until passed) | Tune 2: Daze (two-phase: Entranced → Dazed + Die) | More dynamic, better visual feedback |
| 3-Area level (Tutorial → Escalation → Finale) | Single area level | Time constraint; single area fully playable |
| Advanced Mode: Scroll unlocks Tune 4 | Not implemented | Tune 4 removed from scope |
| Trigger zones wider in Simple mode | Same zones both modes (v1.0) | Simplification; balancing via drain rate instead |
| HTTP DELETE + UPDATE endpoints | Missing in v1.0 | Deferred; POST + 2x GET sufficient for session tracking |
| Spell Charges (Advanced mode) | Removed (TuneController v3.3) | Added complexity without core gameplay value |
| Dynamic collapse timer (Advanced) | Not implemented | Drain rate difference sufficient for difficulty |
